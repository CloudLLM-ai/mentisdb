0.3 Quickstart: Your First Memory

This chapter gets you from zero to a working MentisDB chain with three thoughts and a ranked search, in under five minutes. We'll use the Rust library directly. For Python/TypeScript, see Part 4.

Prerequisites

  • Rust 1.75 or newer (rustup update)
  • A new or existing Rust project: cargo new my_agent --bin

Step 1: Add the dependency

cd my_agent
cargo add mentisdb

That's it. MentisDB has no required external services. The default feature set includes the HTTP/MCP server and LLM extraction helpers. For a minimal library-only integration, use: 

cargo add mentisdb --no-default-features

Step 2: Open a chain

A chain is a directory on disk (or a subdirectory of ~/.mentisdb/chains/). For this quickstart we'll use a temp directory. In production, choose a stable path. 

use mentisdb::{
    BinaryStorageAdapter, MentisDb, ThoughtInput, ThoughtType,
    RankedSearchQuery, ThoughtQuery,
};
use tempfile::TempDir;

fn main() -> io::Result<()> {
    // 1. Open a chain (auto-creates on first run)
    let dir = tempfile::tempdir()?;
    let adapter = BinaryStorageAdapter::for_chain_key(
        dir.path(), "my-first-chain"
    );
    let mut chain = MentisDb::open_with_storage(Box::new(adapter))?;

    // 2. Register an agent
    chain.upsert_agent(
        "planner",
        Some("The Planner"),
        Some("my-team"),
        Some("Plans tasks and records decisions"),
        None,
    )?;

    // 3. Write three thoughts
    chain.append_thought("planner",
        ThoughtInput::new(ThoughtType::Decision,
            "Use Postgres for the events table. \
             Need transactions and joins; DynamoDB's \
             single-region eventual consistency bit us."
        ).with_concepts(["database", "consistency"])
         .with_importance(0.9)
         .with_tags(["prod", "architecture"])
    )?;

    chain.append_thought("planner",
        ThoughtInput::new(ThoughtType::Insight,
            "Throttling at the API gateway is more reliable \
             than per-service limits. We saw 3 incidents \
             where per-service limits failed during deploys."
        ).with_concepts(["reliability", "rate-limiting"])
         .with_importance(0.7)
         .with_tags(["prod", "lessons"])
    )?;

    chain.append_thought("planner",
        ThoughtInput::new(ThoughtType::Constraint,
            "All user PII must be encrypted at rest with \
             envelope encryption. Compliance requirement."
        ).with_concepts(["security", "compliance", "pii"])
         .with_importance(0.95)
         .with_tags(["security", "compliance"])
    )?;

    // 4. Search the chain (returns RankedSearchResult directly)
    let results = chain.query_ranked(
        &RankedSearchQuery::new()
            .with_text("how do we handle rate limiting?")
            .with_limit(5)
    );

    for hit in results.hits {
        // hit.score is RankedSearchScore (ordered_float); cast or use Debug.
        println!("[{:?}] {}", hit.score, hit.thought.content);
    }

    Ok(())
}

Step 3: Run it

cargo run

You should see output similar to:

[0.847] Throttling at the API gateway is more reliable...
[0.312] Use Postgres for the events table...
[0.104] All user PII must be encrypted at rest...
You just built an agent that remembers. The chain is on disk, hash-chained, and queryable. Restart your process, open the same chain, and your thoughts are still there.

What just happened

  1. open_with_storage opened (or created) a chain in the temp directory. The BinaryStorageAdapter writes length-prefixed bincode records — fast and append-only.
  2. upsert_agent registered an agent identity. Agents are persistent: their metadata is part of the chain's registry.
  3. Three append_thought calls wrote durable, hash-chained records. Each got a UUID, an index, and a hash that includes the prior thought's hash.
  4. query_ranked did hybrid retrieval: BM25 lexical scoring ranked the thoughts by keyword overlap with "how do we handle rate limiting?", and the "rate-limiting" concept tag gave the throttling insight a strong signal.

Adding semantic search (vector)

The above used lexical search only. To add semantic similarity, register an embedding provider. The simplest is the local one (no network, no model download): 

// Register a local embedding provider. manage_vector_sidecar
// loads or rebuilds the vector sidecar automatically.
fn enable_semantic_search(chain: &mut MentisDb) {
    chain.manage_vector_sidecar(LocalTextEmbeddingProvider::new())
        .expect("vector sidecar should register");
}

Now every append embeds the new thought and updates the vector index automatically. query_ranked will automatically use both lexical and vector signals.

For better quality embeddings, enable the FastEmbed feature and use the AllMiniL6V2 model (384d, ~90MB download on first use): 

cargo add mentisdb --features local-embeddings

See 3.1 Embedding Provider Selection for when local vs. FastEmbed vs. OpenAI makes sense.

Inspecting the chain

After running, look at the directory: 

ls -la /tmp/.tmpXXXX/my-first-chain/
# my-first-chain.tcbin       # append-only thought log
# my-first-chain.vectors.mentisdb-local-text.v1.256d.json  # vector sidecar

The .tcbin file is the canonical log. Open it with the CLI to inspect: 

cargo install mentisdb --features server
mentisdb list my-first-chain
