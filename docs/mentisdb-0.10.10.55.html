MentisDB 0.10.10.55 — Docker image, private webhook targets, older Linux

October 22, 2026

0.10.10.55 is a deployment release. It does not change how MentisDB stores or retrieves memory; it changes where and how you can run it. There is now an official Docker image, a way to send webhooks to services on your private network, Linux binaries that start on Ubuntu 22.04 and Debian 12, and a daemon that shuts down cleanly when a supervisor asks it to. All three user-facing items came from the community.

1. An official Docker image

@nycterent contributed a Dockerfile and a GitHub Container Registry workflow in #16; we finished it in #24. Every release now publishes a multi-arch image for linux/amd64 and linux/arm64: 

docker run -d --name mentisdb \
  -p 127.0.0.1:9471:9471 -p 127.0.0.1:9472:9472 -p 127.0.0.1:9475:9475 \
  -v mentisdb-data:/var/lib/mentisdb \
  ghcr.io/cloudllm-ai/mentisdb:latest
  • Tags: the release tag (0.10.10.55), the crate version (0.10.10) and latest.
  • Debian trixie base, so local embeddings (FastEmbed over ONNX Runtime) work no matter how old the host is.
  • Runs as a non-root user; chains, skills, TLS certificates and the model cache live in the /var/lib/mentisdb volume.
  • mentisdb --headless under tini, with a HEALTHCHECK on /health. No TTY needed.
  • Publishing refuses a tag that does not match the crate version, so a stray tag cannot move latest; .env files and keys stay out of the build context.

The container listens on all interfaces and a fresh daemon has no authentication, so publish ports on 127.0.0.1 and turn on bearer tokens before exposing it anywhere else. The README has a Compose file and the full list of security notes.

2. docker stop now means a clean shutdown

Getting the image right surfaced a real bug. Headless mode only listened for Ctrl+C, so SIGTERM, which is what docker stop, Kubernetes and systemd send, killed the process without draining its servers. The daemon now registers SIGTERM and SIGINT handlers before it reports ready, shuts the HTTP servers down and exits 0. An integration test runs the headless daemon without a TTY and checks the exit status. The interactive TUI got the same treatment: SIGTERM now restores the terminal and drains the servers too.

3. Webhooks to your private network

0.10.9 hardened webhooks against SSRF by refusing every internal address. takver pointed out in #22 that this also locked out legitimate self-hosted setups, where the webhook consumer sits on a WireGuard or Tailscale network. The new MENTISDB_WEBHOOK_ALLOWED_CIDRS variable opens exactly the ranges you list and nothing else: 

MENTISDB_WEBHOOK_ALLOWED_CIDRS=100.64.0.0/10,fd7a:115c:a1e0::/48

The allowlist is enforced everywhere the guard is: at registration, when saved webhooks are reloaded, and again at delivery time after DNS resolution, so DNS rebinding cannot route around it. localhost stays blocked, any entry broader than /8 is refused (so nobody can re-open half the address space with 0.0.0.0/1), a malformed list stops the daemon at startup instead of being quietly ignored, and a range that covers loopback or the 169.254.169.254 cloud metadata address gets a loud warning.

4. Linux binaries for Ubuntu 22.04 and Debian 12

takver also reported in #21 that our Linux binaries required glibc 2.39 and would not start on Ubuntu 22.04 LTS or Debian 12. The obvious fix, building on an older distro, does not work for the full binary: the prebuilt ONNX Runtime behind local embeddings is itself built against glibc 2.38 and GCC 13. So Linux releases now ship two flavours:

  • mentisdb-linux-x86_64 / -arm64: full features including local embeddings; glibc 2.39+ (Ubuntu 24.04+, Debian 13+).
  • mentisdb-linux-x86_64-compat / -arm64-compat: built on Ubuntu 22.04 without local embeddings (lexical search plus local-text-v1 vectors) and without the startup sound, so no ALSA is needed; glibc 2.34+ (Ubuntu 22.04, Debian 12, RHEL 9).

Run ldd --version to see which one you can use. If you are on an older distro and want local embeddings, use the Docker image. CI now fails the release if a compat binary ever needs a newer glibc than 2.35, so a runner image update cannot silently raise the floor again.

Benchmarks

We did not re-run LoCoMo and LongMemEval for this release. Nothing in retrieval, scoring or embeddings changed since 0.10.9.54, so its numbers still apply.

Upgrade notes

  • No data migration and no breaking changes; webhooks behave as before unless you set MENTISDB_WEBHOOK_ALLOWED_CIDRS.
  • The headless daemon exits 0 on SIGTERM after draining.
  • On Ubuntu 22.04 or Debian 12, download the -compat asset or use Docker.
cargo install mentisdb --locked --force
# or
docker pull ghcr.io/cloudllm-ai/mentisdb:0.10.10.55
